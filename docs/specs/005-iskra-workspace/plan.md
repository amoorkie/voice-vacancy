## 2. Технические решения

| Решение | Причина и компромисс |
| --- | --- |
| Существующий React/Vite и CSS | Не нужен перенос на Next.js только ради сходства с принимающим продуктом |
| Radix Dialog как основа одного составного Sheet; локальные UI-компоненты с токенами shadcn/«Искры» | Официальный shadcn Sheet построен поверх Dialog. Одна модальная область проще для фокуса и двух поверхностей. Полная установка shadcn/Tailwind ради нескольких контролов не обязательна; не называю собственные стили оригинальным кодом «Искры» |
| Существующие Phosphor icons, семантические кнопки и поля; Radix для диалога и необходимых всплывающих контролов | Минимум новых зависимостей. Все визуальные токены изолирую от старого глобального CSS |
| CSS transform для превью, без библиотеки анимации всей страницы | Двигается только левый слой; положение интервью не зависит от анимации родителя |
| Проба Three.js-шейдера в изолированном компоненте, ленивый импорт | Стеклянный эффект ближе к выбранному образу. Цена — вес и управление GPU; нужен fallback |
| Состояние и fixtures в памяти вкладки | Достаточно масштабу демо; после reload нет пользовательских черновиков |

Первичные источники повторно проверены 10.11.2026: [shadcn Sheet](https://ui.shadcn.com/docs/components/radix/sheet), [Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog), [Three.js cleanup](https://threejs.org/manual/pages/cleanup.html), [dispose и служебная память](https://threejs.org/manual/pages/how-to-dispose-of-objects.html), [reduced motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion). Dialog предоставляет управляемое состояние, фокус, заголовок/описание и Escape; конкретное поведение нашего стека всё равно проверяю в браузере. Three.js требует освобождать созданные ресурсы; наличие внутренних кэшей после dispose само по себе не доказывает утечку.

## 4. Состояние и данные

Уровни состояния:

1. **Workspace:** данные демо, `selectedVacancyId`, поиск и фильтры, временные карточки.
2. **Session:** существующие ответы, версии, `active`, результат и ручные правки. Живёт выше панелей и не размонтируется при скрытии превью.
3. **Composer:** закрыт / интервью / превью / подтверждение выхода. Отдельно храню действие, к которому вернуть фокус, и цель выхода. Ошибка генерации привязана к попытке, наличие старого результата проверяется отдельно.

`Session.stage` сохраняет смысл интервью/обзора/результата, но не управляет размером правой панели. Контроллер атомарно согласует UI-переход и доменное действие: открыть ожидающее превью можно только после допустимого `start generation`. Закрытие вызывает отмену ожидания и скрытие слоя, а не `reset`. Повторное открытие использует уже сохранённый `result`; новая генерация — отдельный `start`.

Существующий `Attempt` хранит id, sessionId, question, revision, snapshot, editRevision, phase. Повторно использую `attemptCurrent`; UI не может применить ответ по одному лишь совпадению открытой темы. Для ошибки без результата сохраняю состояние ошибки превью, хотя `Session.active` уже очищен. Не вывожу ошибку из «нет active» — это также нормальное завершение.

### Данные демо

| Сущность | Минимальные поля |
| --- | --- |
| Vacancy | id, title, status active/paused/draft, group, pinned; остальные условия nullable |
| Application | id, vacancyId, displayName вида C-01, replied, testPassed, score nullable, salaryExpectation nullable, experienceYears nullable |
| DemoDraft | id, sourceSessionId, копия шести текущих разделов, пометки/неизвестное, title nullable |

Связи проверяю: уникальные ID, существующая vacancyId, `testPassed ⇒ replied`, согласованность отфильтрованных агрегатов. Топ — сортировка тех же откликов по заданному score; null не превращается в ноль. Границы тепловой карты полуоткрытые, последний диапазон закрыт; записи без данных считаются отдельно. Сумма ячеек и исключённых записей равна выбранному набору.

Начальный набор: 6 вакансий, из них 4 active, 1 paused, 1 draft; 2 pinned. Для выбранной Frontend Engineer — 12 откликов, 8 ответили, 5 прошли тест. Остальные вакансии получают собственные небольшие наборы или явное пустое состояние, без данных предыдущей вакансии. Новая демо-карточка не получает старых откликов. `sourceSessionId` защищает от повторного добавления; сохранение — глубокая копия, дальнейший reset не меняет карточку.

Положительный fixture интервью: frontend-разработчик делает формы кабинета, исправляет обращения и пишет проверки; в первые шесть месяцев выпускает кабинет работодателя с готовым API; затем развивает его, аналитика пока под вопросом; React/TypeScript/доступные формы обязательны, Playwright желателен. Зарплата, город и формат не заданы. Результат отражает каждый факт и неопределённость. Неподдержанные правки получают честный ответ «Для этого текста нет тестового результата», а не неподходящий шаблон.

## 5. Геометрия без сдвига интервью

Для desktop W ≥ 1200 CSS px:

- `interviewWidth = 560`, `inset = 16`, `overlap = 16`.
- `previewWidth = min(720, W − 576)`. На 1200 это 624 px, на 1280 — 704 px, от 1296 — 720 px.
- Правая панель закреплена `right: 16px`; у левой итоговый правый край находится на 560 px от правого края окна. Нахлёст составляет 16 px.
- Общая ширина с наружными отступами: `560 + previewWidth − 16 + 32`. Она не превышает W. Контент превью имеет безопасный внутренний отступ со стороны нахлёста.

Слой интервью имеет постоянный z-index выше превью. Новая панель до появления скрыта маской; при движении её не должно быть видно справа от интервью. Анимирую превью, не ширину modal host и не интервью. При закрытии оставляю DOM превью только на время обратной анимации, после чего удаляю из фокуса/рендеринга; данные остаются в Session. При reduced motion скрываю сразу.

Обработчик открытия во время закрывающей анимации возвращает одну существующую панель, не создаёт ещё одну. Применение данных не зависит от `transitionend`: событие может не прийти при reduced motion или смене viewport.

На 640–1199 показываю один активный слой. На мобильном — полный доступный экран. Это отдельный адаптивный режим; при resize между режимами сохраняю текст, выбор темы, редакцию и фокус. Правую панель не сжимаю внутри desktop-анимации.

## 6. Фокус, закрытие и прокрутка

У одного Dialog есть заголовок и описание; фон заблокирован. Пока активно превью, интервью исключено из фокуса и взаимодействия, но остаётся на месте. По «К ответам» фокус возвращается к инициировавшему действию, с запасным доступным заголовком, если кнопка исчезла. Старое действие не фокусируется через скрытый слой.

Все причины закрытия проходят один обработчик: кнопка, Escape, фон, переход к подключению. При открытом подтверждении сначала закрывается/отменяется оно. Для подтверждения внутри composer использую управляемое состояние того же modal host, не оставляю действующий нативный `showModal()` поверх Radix с конкурирующим фокусом. В сохранении в демо есть явный путь завершения без повторного вопроса о потере уже скопированного результата.

Прокрутка у панелей отдельная; колесо на границе не прокручивает фон. Выбор темы прокручивает только её редактор. Автопрокрутка расшифровки действует только у нижнего края; ручное чтение старых строк не прерывается. После закрытия превью восстанавливаю позицию интервью.

## 7. Шар: проба и включение

Основной кандидат — [MIT Siri-демо](https://github.com/neeldedkawala/ios-siri-animation), изученное в исследовании. Выделяю только эффект, без телефона, обоев и иконок. Перед переносом фиксирую исходный commit и лицензионные уведомления; это не официальный код Apple. Сначала отдельная проба в форме круга на нашем светлом фоне, затем подключение.

Контракт компонента: `mode` idle/recording/processing/error, `levelRef` 0…1, reducedMotion и доступная кнопка записи. Прогресс не входит в renderer — его показывает существующий ProgressRing. Кнопка и подпись живут вне canvas, поэтому ошибка WebGL не лишает управления.

В F005 подаю детерминированный тестовый сигнал, без `getUserMedia`. Renderer читает ref в animation frame, а не меняет React state каждую итерацию. Ограничиваю DPR до 2; импорт откладываю до открытия интервью. Шум/текстуры — локальные или процедурные. Если проба не выдерживает визуальную проверку, оставляю нынешний стеклянный fallback и показываю сравнение; не подменяю образ ElevenLabs Orb молча.

При cleanup останавливаю собственный RAF, снимаю обработчики, освобождаю созданные geometry/material/texture/render target/renderer. Проверяю ресурсы компонента до и после 20 циклов, а не требую нулевой общей памяти браузера. Ориентир на проверяемом desktop: p95 интервала кадров ≤33 ms за 10 секунд после прогрева; p95 реакции ввода ≤100 ms. В отчёте фиксирую устройство/браузер/нагрузку. При провале упрощаю эффект или использую fallback; цифры являются критериями этой пробы, не обещанием на всех устройствах.
