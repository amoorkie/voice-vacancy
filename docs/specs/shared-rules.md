# Общие правила четырёх функций

Status: accepted
Принятие: [product-v1 от 10.11.2026](../product/accepted-decisions-2026-11-10.md).
Дата: 10.11.2026

Я собираю здесь правила, которые должны одинаково работать в интервью, записи, проверке ответа и генерации. Названия полей нужны разработчику; рядом я объясняю их смысл. Реализации пока нет.

## Требования

- **SH-R1:** при начале и полном сбросе интервью я создаю новый `sessionId`. Он не повторяется. Обычный переход между темами сохраняет сеанс. Запрос сброса открывает подтверждение; только согласие удаляет данные и отменяет запросы. Отмена диалога сама ничего не удаляет.
- **SH-R2:** я храню рабочий текст отдельно от последнего подтверждённого. `revision` меняется при каждом реальном изменении рабочего текста. `confirmedRevision` меняется только при подтверждении другого содержимого. Подтверждение того же текста сохраняет прежнюю подтверждённую версию. Пробелы удаляются только для проверки пустоты; исходный текст не обрезается молча.
- **SH-R3:** изменение подтверждённого ответа снимает его подтверждение. Возврат к прежним словам вручную сам не подтверждает ответ. «Отменить изменения» явно возвращает подтверждённый текст и статус. Если подтверждённого текста ещё нет, отмена очищает рабочую версию. Другие темы сохраняются. Отменённые запросы не возобновляются после возврата текста.
- **SH-R4:** каждая попытка получает новый `requestId`. Для записи/расшифровки и проверки смысла принимаю ответ только для активной попытки в том же сеансе, теме и рабочей версии, до срока ожидания. Для генерации вместо одной темы проверяю весь snapshotId и draftEditRevision по F004-R6. У отменённой, просроченной или заменённой попытки результат отбрасывается даже при совпадении текста. Для проверки смысла дополнительно совпадает версия правил оценки. Служебные идентификаторы задаёт приложение, модель не выбирает их сама.
- **SH-R5:** `snapshotId` обозначает состав четырёх подтверждённых версий в одном сеансе. Генерация использует только их. Пока хотя бы одна тема изменена и не подтверждена, старый черновик помечен устаревшим. Возврат к прежнему подтверждённому снимку восстанавливает актуальность. `draftEditRevision` отдельно отмечает правки самого черновика и защищает их от позднего ответа генератора.
- **SH-R6:** я не применяю неполный или неверно устроенный ответ сервиса. До показа проверяю обязательные поля, допустимые значения, полноту списков, отсутствие повторных ID и связь цитат с входом. Входные слова и ответы модели считаю данными; интерфейс показывает их как текст, без выполнения HTML или команд. Наличие цитаты не доказывает смысловую верность утверждения — это проверяется отдельно.
- **SH-R7:** тайм-аут отсчитываю с отправки запроса. В срок входят передача данных и ожидание ответа. По истечении срока попытка становится неактивной; поздний ответ не применяется. Повтор возможен только по нажатию и получает новый ID. Одновременно активна максимум одна попытка каждого вида для текущего редактируемого ответа, а генерация — одна на сеанс.
- **SH-R8:** храню ответы, временные записи и черновик в памяти открытой страницы. Ключей провайдера в браузере и Git нет; содержимое не попадает в обычные логи. Перед реальной интеграцией фиксирую провайдера, его обработку/хранение данных, серверные ограничения частоты и расходов. Отмена в интерфейсе не обещает отменить уже выполненную внешнюю обработку.

## Поля, на которые я ссылаюсь в спеках

| Поле | Что оно означает |
| --- | --- |
| sessionId | Текущее интервью; меняется при полном сбросе |
| questionId | Одна из четырёх тем: Q1, Q2, Q3, Q4 |
| draftText / revision | Рабочий текст и его версия |
| confirmedText / confirmedRevision | Последний подтверждённый текст и его версия |
| isConfirmed | Подтверждена ли текущая версия темы |
| requestId | Отдельная попытка обработки; повтор не использует старый ID |
| snapshotId | Состав четырёх подтверждённых версий |
| draftEditRevision | Версия ручной редакции итогового черновика |
| followUpUsed | Было ли уже показано одно уточнение в этой теме |

При применении ответа сервиса я повторно проверяю актуальность, даже если она проверялась при отправке. Отмена может прекратить ожидание без физической остановки внешнего сервера; пришедший позже результат всё равно не применяется.

## Ограничения первой версии

Эти числа входят в контракт первой версии. 120 секунд и 6000 единиц приняты в product-v1; остальные пределы сохраняю для реализации. Они не являются условиями исходного задания или обещанием скорости провайдера. Совместимость и реальную задержку проверю до включения интеграции.

| Ограничение | Значение и точный смысл |
| --- | --- |
| Ответ на одну тему | До 6000 Unicode code points; это единицы Unicode, не байты и не длина UTF-16 |
| Запись | До 120 секунд по таймеру интерфейса; источник счёта — начало записи, не ожидание разрешения |
| Файл для отправки | Больше 0 и не больше 10 MiB: 10 485 760 байт после сборки всех частей |
| Расшифровка | 45 секунд с отправки |
| Оценка ответа | 20 секунд с отправки |
| Генерация | 60 секунд с отправки |
| Сгенерированный текст | До 12 000 Unicode code points суммарно по текстовым полям, включая неизвестное и конфликты; превышение отклоняется, не обрезается |

Сервер повторно проверяет входные ограничения. В техническом плане я проверю, что сервис принимает четыре полных ответа по 6000 единиц вместе с инструкциями и возвращает нужный объём. Если ограничения сервиса меньше, сначала изменю спецификацию; скрытого сокращения ответа не будет.

## Критерии приёмки

Это будущие проверки. Сейчас я не выдаю их за результаты тестов приложения.

| ID | Требования | Что я делаю | Что ожидаю |
| --- | --- | --- | --- |
| SH-AC1 | SH-R1, SH-R4 | Начинаю запрос в Q1, подтверждаю полный сброс, получаю старый ответ в новой Q1 | Новый sessionId; старый ответ не меняет новый сеанс |
| SH-AC2 | SH-R2, SH-R3 | Подтверждаю текст, меняю его, вручную возвращаю прежние слова | Подтверждение остаётся снятым до явного действия |
| SH-AC3 | SH-R2, SH-R3, SH-R5 | После правки нажимаю «Отменить изменения» | Старые текст/подтверждённая версия и актуальность их черновика восстановлены |
| SH-AC4 | SH-R4, SH-R7 | Отменяю попытку, запускаю повтор, затем получаю ответ первой | Примениться может только повтор, даже если вход одинаковый |
| SH-AC5 | SH-R4, SH-R7 | Ответ приходит после срока ожидания | Видно восстановление, текст сохранён, поздний результат отброшен |
| SH-AC6 | SH-R6 | Сервис возвращает пропущенное поле, повторный ID или чужую цитату | Ответ отклонён; прежний материал и путь продолжения сохранены |
| SH-AC7 | SH-R6 | Ввожу HTML и инструкцию изменить правила системы | Они остаются текстом и не меняют контракт обработки |
| SH-AC8 | SH-R8 | Закрываю и заново открываю страницу | Старый сеанс не восстанавливается; это было объяснено до ввода |

## Что я уточню до кода

Поведение, русский язык и целевые desktop Chrome/Edge приняты в product-v1. Перед кодом фиксирую технический план, правила внешнего хранения, частоту запросов и бюджет. Принятые требования не означают разрешение на оплату или успешную проверку сервиса.

Технические решения записаны в [плане](../technical/plan.md), [контракте данных/API](../technical/data-and-api.md) и [бюджете](../technical/services-and-budget.md). Сроки ожидания являются правилами отмены, а не обещанием SLA провайдера.
