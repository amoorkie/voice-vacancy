# Последовательность PR и комплект сдачи

Я развиваю проект небольшими PR. Это порядок работы без обещания сроков; номера этапов не являются заранее выданными ID в GitHub.

| Этап | Содержание | Условие перехода |
| --- | --- | --- |
| Основа, начальный commit | Git, README, инструкции, `docs` | Репозиторий доступен |
| Discovery PR | Brief, аналоги, JTBD, user flow, scope, процесс, docs-check | Владелец рассматривает предлагаемые продуктовые решения |
| Draft specs PR | Спецификации интервью, голоса, полноты и генерации | Закрыть блокирующие вопросы и принять релевантные спецификации |
| План и каркас приложения | Стек, визуальное направление, структура, проверяемый запуск и CI | Сборка и первый согласованный экран проверены |
| Интервью | Четыре темы, текст, редактирование, подтверждение, прогресс, сводка и экспорт | Сводка имеет полезный выход без генерации; текстовый срез ещё не закрывает BR-02 |
| Голос | Реальная запись и транскрибация, разрешения и восстановление | Реальный проход с микрофоном и контроль ошибок |
| Полнота | Рубрика и одно уточнение | Контрольные примеры и понятность человеку |
| Черновик | Опциональная генерация поверх сводки, редактирование и экспорт | Источники и пробелы видны; сохранены правки и выход при недостаточности данных |
| Приёмка и сдача | Полный проход, описание, презентация, отчёт о процессе, демо/видео | Все согласованные критерии имеют доказательства |

Полнота и генерация выделены отдельно, чтобы ошибки оценки не блокировали базовый сценарий незаметно. Текстовый срез помогает проверить flow, но до добавления настоящего голоса нельзя объявлять минимум исходного задания выполненным.

Рекомендую сдавать полную цель F001–F004; уровень ещё нужно принять. Если принят полный уровень, генерация обязательна как работающая возможность, хотя человек вправе забрать только сводку. Варианты min/medium и границы результата перечислены в [brief](../product/brief.md).

## Комплект сдачи

- Публичный репозиторий с читаемыми PR и документацией.
- Работающий прототип по согласованному адресу либо короткое видео при невозможности деплоя.
- Описание функции и небольшая презентация для пользователя.
- Фактический список сделанного, отложенного и ограничений.
- Объяснение последовательности, методик, спецификаций и использованных промптов с версиями; отдельный перечень работы человека и ИИ. В ТЗ запрошен процент участия ИИ: перед сдачей нужно указать основу расчёта либо явно обозначенную приблизительную оценку автора с её методом. Сейчас данных для числа нет; не выдаю отсутствие измерения за выполненное требование.

## Материалы разработчика, BR-07

| Комплект | Что я подготовлю к сдаче | Как проверю |
| --- | --- | --- |
| Min | Запуск с чистого checkout, версии зависимостей, пример конфигурации без ключей, команды сборки/проверок, схема компонентов и обработки данных, ошибки/ограничения | Другой разработчик может запустить проект по README и понять связь поведения с кодом |
| Дополнение для агентной разработки | Принятые спеки, plan/tasks, точные контракты/фикстуры, версии промптов и рубрик, инструкции AGENTS, границы изменений, verification с SHA и открытыми вопросами | По документам можно выбрать следующую задачу, выполнить её и проверить без домысливания поведения |

Наличие четырёх draft сейчас не закрывает ни один из этих комплектов целиком. До кода допускаются вопросы; в принятом объёме реализации не должно оставаться неопределённых состояний, ошибок, запретов и контрактов.

## Пять критериев оценки задания, BR-10

| Критерий | Что предъявлю | Что есть сейчас |
| --- | --- | --- |
| Понимание задачи | Связь исходного brief с выбором функций и явными исключениями | Brief, исследование, JTBD, сценарий и предложения scope |
| Достаточность спецификации | Состояния, ошибки, запреты, контракты, принятые решения | Draft-спеки; O1–O5 и технические планы ещё открыты |
| Работоспособность | Реальный проход от голоса до результата на заявленном уровне | Приложения, deploy и видео пока нет |
| Работа с ИИ | Журнал задач, промпты/версии, разделение работы и понятная оценка доли ИИ | Журнал есть; численная оценка и промпты будущего приложения отсутствуют |
| Объяснение решения | Краткое описание и презентация для пользователя, защита компромиссов | Обоснования есть в docs; презентация ещё не подготовлена |

Публикацию приложения и слияние PR я выполняю отдельным решением. Название репозитория, наличие документов и успешный CI ещё не являются сдачей работающего задания.
