# Проверка адаптера моего API

Дата: 10.11.2026. Статус: локальные проверки выполнены; реальная генерация заблокирована доступом к провайдерам. Проверяемый код — коммит реализации, содержащий этот отчёт; он продолжает PR #4 на `8669f6d124449d05e12d24990cb88c2b44b385bd`.

## Что я проверил

Через Codex выполнены typecheck, сборка и 33 unit-теста. Они проверяют входные данные, Host/Origin и токен процесса, отсутствие ключа в ответах, лимиты и журнал попыток, повтор ID, тайм-аут, обрыв и пустой JSON, цитаты, версии источников и шесть разделов черновика.

В Chrome и Edge прошли 24 браузерные проверки: тестовый путь и режим API с подставными сетевыми ответами, ошибки без подмены результатом, сохранение текста, источники и ручные правки. Эти проверки не используют настоящий ключ и не доказывают качество модели.

## Что показал реальный шлюз

Первый ключ: 403 `INSUFFICIENT_BALANCE`. Заменяющий ключ: `/models` отвечает 200, DeepSeek запрещён группой. После моего согласия на GPT проверены `gpt-5.4-mini`, `gpt-5.2`, `gpt-5.4`, `gpt-6-luna`, `gpt-6.1-sol` через Chat Completions; `gpt-5.4-mini` и `gpt-6-luna` также через Responses, последний — с потоковым и обычным ответом. Все попытки генерации вернули 404 `model_not_found` до ответа модели.

Read-only проверка актуального маршрута, конфигурации провайдеров и правила доступа показала: ключ активен; четыре активных разрешённых к планированию провайдера его GPT-группы относятся к личным аккаунтам других владельцев. Для этого ключа они недоступны. Каталог моделей не является доказательством доступной генерации. Настройки сервиса, права, БД и маршруты не изменялись. Идентификаторы аккаунтов, ключи, внутренние адреса и журналы с данными пользователей в репозиторий не включены.

## Что осталось

- Подключить доступный владельцу ключа провайдер либо дать ключ рабочей группы. Это действие на основном сервисе, отдельно от Voice Vacancy.
- Подтвердить модель и протокол успешным запросом. Сейчас в приложении реализован Chat Completions; необходимость перехода на Responses проверю после восстановления доступа.
- Пройти реальную оценку и генерацию на вымышленных данных, затем корпус качества из технических задач. Локальный лимит 20 попыток не покрывает весь корпус; его расширение и цену согласую отдельно.
- Подтвердить стоимость и условия хранения данных шлюзом. Ответов с usage пока не получено; отсутствие таких ответов не доказывает отсутствие списаний.

Микрофон, ASR, выбранный новый дизайн, пользовательские исследования, merge и deploy сюда не входят.
