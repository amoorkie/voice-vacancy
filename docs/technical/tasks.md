## Корпус и пороги качества

Эти проверки запланированы, ни одна ещё не выполнена. Ожидаемые результаты фиксирую **до** запроса модели. В Git только вымышленные тексты; тестовые записи хранятся вне репозитория с согласием записавшего.

- **ASR:** 12 русских записей: четыре темы, тихий/шумный фон, SQL/CRM и другие англоязычные названия, числа, отрицания, самоисправление, короткое «не знаю», длинная запись и тишина. Для речевых примеров заранее выписываю важные факты/отрицания. Приёмка: ни одной инверсии смысла, потери критичного факта или выдуманной задачи; ≥95% заранее отмеченных сущностей распознаны верно; тишина не создаёт содержательный ответ. Ошибки пунктуации не равны потере смысла. До исправления критичных ошибок заявлять качество нельзя.
- **F003:** C1–C14 × 3 независимых запуска = 42 проверки. На каждом прогоне ожидаемые статусы, точные цитаты и конфликты должны совпасть; ни одного пропущенного/дублированного slotId или второго уточнения. Нестабильный пример — открытый дефект, не усреднённый успех.
- **F004:** восемь полных наборов ответов × 3 = 24 генерации: определённая роль, неизвестное название, неизвестные темы, недостаточный ввод, противоречие, самоисправление, разные полугодия, добровольно названные условия/отрицания. Для каждого заранее готовлю список фактов, которые надо сохранить, и недопустимых выводов. Приёмка: 100% обязательных исходных фактов сохранены, 0 выдуманных/усиленных требований и 0 неверных ссылок; все шесть разделов либо ожидаемый insufficient-input.
- **Скорость:** каждый прогон фиксирует upload + ожидание до результата; все приёмочные записи должны уложиться в 45/20/60 секунд. p50/p95 показываю описательно, без обещания статистической гарантии на маленьком наборе. Превышение срока проверяет fallback, но не считается успешным прохождением интеграции.
- **Бюджет:** после корпуса сверяю расчёт и фактический usage, отменённые/неудачные попытки и остаток. Для предварительной оценки в бюджете считаю 42 проверки по 2000/600 токенов, 24 генерации по 6000/2000 и 10 обычных интервью.

При провале сначала исправляю prompt/контракт/адаптер и повторяю затронутые примеры плюс регрессии. Более дорогую модель или другого провайдера не включаю автоматически: сначала обновляю план данных и стоимость. Сами тесты оплачиваются только после T10.
