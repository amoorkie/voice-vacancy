# DeepSeek и обработка ответов

Актуальный опубликованный сценарий — [создание вакансии](https://amo0orkie.ru/iskra/). На 11.11.2026 сервер настроен на `ds/deepseek-v4.1-flash` через `https://api.wikivibe.dev/v1`. Повторный публичный проход вернул 200 на генерацию, после чего прошли редактирование, копирование и скачивание результата. [Отчёт](../verification/007-real-voice.md).

## Как идёт запрос

1. Я отвечаю на четыре вопроса. Успешная расшифровка автоматически завершает тему, текст завершаю по Enter. Исправить ответ можно через его бейдж.
2. После четвёртого ответа браузер автоматически открывает превью и отправляет подтверждённые тексты своему серверу на `/iskra/api/vacancy`.
3. Сервер проверяет вход, версии ответов, Origin, токен и доступный лимит попыток.
4. Сервер обращается к моему шлюзу по Chat Completions. Модель получает отдельный промпт и ответы как данные.
5. Полученный JSON проходит проверку шести разделов и ссылок на точные цитаты из подтверждённых ответов.
6. В браузере открывается вакансия. Могу поправить текст и забрать свою редакцию.

Промпт версии `owner-text-v1` находится в [src/server/prompts.ts](../../src/server/prompts.ts). В нём заданы русский язык, задачи и требования, неизвестные данные, отрицания, противоречия, обязательные и желательные знания. Факты должны опираться на цитаты. Название роли и условия берутся из явных слов руководителя.

## Что проверяется

- JSON соответствует схеме и содержит ровно шесть разделов.
- Для утверждений о фактах указаны вопрос, версия и дословная цитата.
- Цитаты относятся к текущим подтверждённым ответам.
- Незнание и конфликт сохраняются отдельными видами утверждений.
- Запоздалый результат отменённого запроса исключается из применения.
- Перед повторной сборкой ручной редакции требуется подтверждение.

Проверки формата и цитат выполнены автоматически. Итоговый смысл и формулировки руководитель проверяет в редактируемом превью.

## Конфигурация

Ключ, модель и адрес шлюза задаю в env на сервере. На опубликованном экземпляре это `/etc/voice-vacancy/app.env`, в локальном запуске — `.env`. Путь backend и публичный Origin описаны в [инструкции размещения](deployment.md). Ключ и системный промпт хранятся на сервере.

Модель выбирается явно через `WIKIVIBE_MODEL`. Автоматической замены модели нет. `GET /api/config` сообщает режим, ID модели и случайный токен процесса. В опубликованном разделе к маршрутам добавляется префикс `/iskra/`.

`AI_ENABLED=false` включает готовые примеры. При настроенном API ошибка возвращается как ошибка с сохранением ответов и предыдущей вакансии.

## Лимиты и ошибки

Сохраняю общий предел в 20 внешних попыток, максимум одну одновременно и шесть в минуту. Счётчик хранится вне Git, на сервере — отдельно от релиза. Отмены, ошибки и незавершённые попытки учитываются в лимите. Перезагрузка страницы и смена релиза сохраняют расход.

Тексты ограничены 6000 Unicode code points на ответ. Максимум модели — 8192 токена для черновика, вывод длиннее 12000 code points отклоняется. Тайм-аут генерации — 60 секунд. После ошибки можно повторить действие вручную.

Сервер сообщает ошибки сети, авторизации, баланса, лимита и структуры ответа. При отказе скопировать текст остаётся скачивание .txt.

## Дополнительный контракт

Адаптер также поддерживает `/api/completeness` для F003 и первого самостоятельного экрана `?view=interview`. Он принимает текущий ответ, проверяет rubric-v1 и возвращает причины, точные цитаты, конфликты и максимум один уточняющий вопрос. Его тайм-аут — 20 секунд, максимум ответа — 4096 токенов.

Ранняя история подключения сохранена в [отчёте по первому ключу](../verification/002-owner-api.md). Текущее состояние подтверждено [публичным проходом](../verification/007-real-voice.md).


## Распознавание речи

Микрофон передаёт собственному серверу WAV PCM16 mono, 16 кГц и максимум 120 секунд. Маршрут `/api/transcriptions` проверяет Origin, токен, формат, размер и наличие звука. faster-whisper 1.2.1 с моделью base int8 и Silero VAD распознаёт русский язык на CPU. Один процесс за раз, до шести запросов в минуту, срок обработки 45 секунд. Аудио поступает через stdin и память процесса, после обработки освобождается. Nginx передаёт запрос без записи тела во временный файл. Дополнительного платного API для аудио нет. DeepSeek получает подтверждённые тексты.

Обнаружено, что доступные по текущему ключу модели шлюза отклоняют audio input. Поэтому аудио обрабатывается на своём сервере. В публичном режиме подстановка готовых ответов удалена. Готовые примеры доступны в отдельной конфигурации fixtures для разработки.
