# Мой API: первый текстовый проход

Дата: 10.11.2026. Status: accepted для подключения по моей команде «подруби сразу». Этот документ заменяет запрет внешних вызовов в предыдущем тестовом срезе. Публичное размещение и настоящая запись сюда не входят.

## Что я подключаю

Я использую `https://api.wikivibe.dev/v1` для F003 (проверка текущего текста по rubric-v1) и F004 (черновик по четырём подтверждённым ответам). После проверки доступа я разрешил GPT вместо DeepSeek командой «гпт норм». Ключ хранится только в локальном `.env`, исключённом из Git. Прямых обращений приложения к OpenAI нет: все запросы идут в мой шлюз.

Модель задаю явно через `WIKIVIBE_MODEL`; автоматического выбора и замены провайдера нет. В адаптере реализован Chat Completions с JSON-ответом. Его совместимость с доступным мне провайдером пока не подтверждена. Аудио остаётся явно подписанной локальной имитацией.

Первый ключ получил 403 `INSUFFICIENT_BALANCE`. Заменяющий ключ активен и получает каталог моделей, но реальные генерации возвращают 404 `model_not_found`: проверены Chat Completions и Responses, включая потоковый запрос. Read-only проверка текущего шлюза установила, что все четыре активных разрешённых к планированию провайдера в GPT-группе являются личными аккаунтами других владельцев. Проверка доступа исключает их для моего ключа. Каталог моделей не подтверждает доступ к генерации.

До продолжения нужен провайдер, доступный владельцу ключа. Настройки общего шлюза, доступы и данные я не менял. После устранения причины проверю фактическую пару модели и протокола; при необходимости заменю транспорт адаптера на Responses. Подключение считается незавершённым до реального успешного прохода.

## Границы данных и расходов

По явной кнопке проверки отправляю текущий ответ, по кнопке генерации — четыре подтверждённых текста. Автопроверки при вводе и скрытых повторов нет. До начала интервью объясняю, что текст отправляется в мой API; сроки хранения этим сервисом пока не подтверждены. Локальный сервер не пишет текст, ключ и ответы провайдера в файлы/логи.

Для первого локального прохода ставлю предел **20 внешних запросов всего**, максимум один одновременно и шесть в минуту. Счётчик сохраняется вне Git до отправки; отмены, ошибки и незавершённые попытки не возвращают резерв. Перезагрузка страницы/сервера не обнуляет его. Повреждение файла, невозможность записи и второй процесс отключают новые вызовы. Это предел попыток, не обещание денежного бюджета: тариф моего шлюза неизвестен. Новый лимит задаю осознанно в локальной конфигурации после сверки баланса.

Тело запроса ограничено; каждый текст — 6000 Unicode code points. Максимальный ответ модели — 4096 токенов для оценки и 8192 для черновика; вывод свыше 12000 code points отклоняю целиком. Deadline — 20 и 60 секунд. Автоповторов нет; отмена не гарантирует отмену списания на стороне сервиса.

## Контракт и защита

Сервер принимает только фиксированные операции с валидированным JSON. Браузер не выбирает endpoint, модель или system prompt. Сервер работает на loopback; проверяет Host, Origin и случайный токен своего процесса. Ни ключ, ни системные инструкции не включаются в клиентский bundle. Режим фикстур выбирается конфигурацией до запуска; ошибка API не подменяется готовым примером.

Оценка содержит все пункты rubric-v1, причины, точные цитаты и конфликты; одно уточнение ограничивается состоянием сеанса. Черновик содержит шесть разделов с отдельными утверждениями и источниками `questionId/confirmedRevision/quote`. Неизвестное и конфликт отличаются от факта. Схему и точность ссылок проверяю до применения. Это не доказывает смысловую правильность: полный корпус качества остаётся отдельной проверкой после восстановления доступа к провайдеру.

При ошибке баланса, авторизации, сети, лимита или структуры сохраняю текст и прежний результат. Поздний ответ отменённой попытки не применяется. Ручные правки снимают показ машинных источников с изменённого раздела.

## Приёмка подключения

1. Внешний ключ отсутствует в Git и клиентской сборке; браузер обращается только к своему серверу.
2. Неверный origin/token/вход, повтор ID, лимит и повреждённый журнал не вызывают провайдера.
3. Структурно неверная оценка/черновик, чужие цитаты, неправильные версии, обрыв JSON и пустой ответ не применяются.
4. Отмена, тайм-аут, ошибка баланса и повтор сохраняют работу; fixture-режим остаётся проверяемым без сети.
5. После восстановления доступа: каталог моделей и минимум одна реальная оценка и генерация на вымышленных данных. Пока этот пункт не пройден, интеграция не считается проверенной с моделью.

Основание формата: [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create), просмотрено 10.11.2026. Это описание протокола; совместимость шлюза проверяю отдельно. Результаты проверок — в [отчёте](../verification/002-owner-api.md).
