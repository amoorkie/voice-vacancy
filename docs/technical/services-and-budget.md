## Доступность и данные

OpenAI разрешает доступ только в [перечисленных странах и территориях](https://developers.openai.com/api/docs/supported-countries); России в списке нет. Я не определяю страну владельца по языку интерфейса. До включения проверяю аккаунт, платёжный профиль, место сервера и страны, где будет доступно демо. Если условия не подходят, OpenAI не включаю и отдельно довожу резервный вариант до проверенного плана; обход ограничений не планирую.

У OpenAI для `/audio/transcriptions` в таблице хранения указаны отсутствие использования для обучения и отсутствие хранения состояния/abuse logs. Для `/responses` обучение также не включено по умолчанию, но возможны abuse logs до 30 дней. `store=false` отключает сохранение ответа как состояния API, а не все виды хранения. Кеширование и исключения зависят от выбранных возможностей; ZDR для аккаунта не подтверждён. Основание: [Data controls](https://developers.openai.com/api/docs/guides/your-data). Поэтому я не обещаю «данные нигде не сохраняются». Полный жизненный цикл задаю в [контракте данных](data-and-api.md).

## Тариф для расчёта

По [официальному прайсу](https://developers.openai.com/api/docs/pricing), Standard для GPT-6 Luna: $0,10 за 1 млн входных и $0,50 за 1 млн выходных токенов. Cache write стоит $0,125 при 30 минутах и $0,25 при 12 часах. Для консервативной оценки ниже считаю **весь вход по $0,25/млн**, даже без попаданий в кеш. Скидки, бесплатные кредиты, Batch/Flex и подписку ChatGPT не учитываю. Региональные надбавки, налоги, обмен валют и комиссии оплаты в таблицу не входят.

Формула: `минуты × 0.0045 + входные токены / 1_000_000 × 0.25 + выходные токены / 1_000_000 × 0.50`. Токены — единицы расчёта модели; они не равны символам. Выход учитывает все оплачиваемые выходные токены, включая reasoning, если режим позже изменится.

Это предположения об объёме, а не замеры. Вход включает инструкции, JSON Schema и ответы. Полные лимиты по символам не являются средней длиной.

В третьей строке восемь записей по две минуты, восемь проверок по 7000 входных/1000 выходных токенов и две генерации по 16000/6000. В первой — проверки по 2000/600 и генерация 6000/2000; во второй — проверки по 3500/700 и генерация 8000/3000. Повторная запись и ручная повторная обработка оплачиваются заново. Ошибка или отмена после отправки не гарантирует отсутствие списания.

Десять прогонов обычного интервью, 42 проверки рубрики и 24 генерации на вымышленных примерах дают $0,42978 с тем же запасом при указанных в задачах размерах. Ещё 12 тестовых записей по две минуты добавят $0,14040: итого около **$0,60** до дополнительных повторов. Начальный резерв для проверок предлагаю **$3**, общий API-бюджет разработки и первого демо — **$15**. Эти суммы ещё не одобрены к расходованию. После первых платных проверок пересчитываю прогноз по фактическому usage.

## Размещение и общий бюджет

Локальная разработка с фикстурами не требует платных сервисов. Для будущей публичной демонстрации выбираю один Render Web Service `0.5c-512mb` (бывший Starter) около $7/месяц и постоянный диск 1 GB около $0,25/месяц для счётчика расходов. Основания: [официальная таблица compute-планов](https://render.com/articles/set-up-self-hosted-github-actions-runners-on-render), [диск и стоимость](https://render.com/articles/how-much-does-cloud-application-hosting-cost-for-small-businesses), [правила дисков](https://render.com/docs/disks), [прайс](https://render.com/pricing).

Сумма первого месяца с предлагаемым API-лимитом: **$22,25 до налогов и доплат**. Это $15 резерва API + $7,25 хостинга, а не обязательный ежемесячный расход на модель. Для 100 обычных интервью расчёт потребления с запасом и хостингом — около **$10,33**. Платный домен, БД, S3, сервис рассылок и платная аналитика не нужны. Трафик и минуты сборки проверю по действующему workspace-плану перед deploy; без этого $22,25 не является гарантированным пределом общего счёта.

Free-хостинг не выбираю для платного публичного AI: [Render Free](https://render.com/docs/free) не поддерживает постоянный диск. Сброс счётчика после перезапуска позволил бы заново потратить лимит. Постоянный диск хранит только технический учёт, без ответов и аудио. Публичный запуск остаётся отдельным решением.

## Как я ограничиваю расход

- По умолчанию `AI_ENABLED=false`, лимит расходов равен нулю. Наличие ключа само не включает обработку.
- После согласования суммы отдельно задаю общий лимит, например $15, дневной $3 и резерв проверок $3 внутри общего. Это выбранные настройки, не уже выданное разрешение на оплату.
- До каждого вызова сервер резервирует стоимость максимального допустимого запроса. Предельные резервы первой версии: ASR $0,01, проверка $0,02, генерация $0,08. Если проверенный тариф/лимиты не укладываются, запрос не отправляется до пересмотра резерва.
- Максимум три внешних запроса одновременно на сервер, один каждого вида на сеанс; в очереди запросы не коплю. Лимиты частоты и атомарный учёт описаны в контракте. Сброс интервью не сбрасывает общий бюджет.
- Счётчик переживает рестарт. Отсутствующий/повреждённый счётчик блокирует внешние вызовы; его нельзя автоматически обнулить. При неизвестной стоимости отменённой попытки сохраняю весь резерв до сверки.
- Повторы только по действию человека; автоматические retries SDK выключаю. Изменение модели или тарифного режима требует пересчёта до включения.

Расчётные значения также сохранены в [budget-estimate.json](budget-estimate.json), чтобы проверить арифметику независимо от текста.
