# ADR 0001: облегчённая основа SDD

Дата: 10.11.2026. Статус: решение об обратимом устройстве репозитория; продуктовые гипотезы остаются на review.

Я выбираю небольшую основу, которую смогу объяснить и проверить без лишних инструментов.

## Контекст

Нужно показать обоснованный процесс небольшого тестового проекта: исследование до спецификаций, спецификации до кода, изменения через PR. Стек и провайдеры пока неизвестны. В текущей папке не было исходного кода или истории коммитов; новый постоянный проект создан в `D:\Codex\Projects\voice-vacancy` по моим правилам размещения.

## Варианты

| Вариант | Польза | Цена |
| --- | --- | --- |
| Свободные заметки и сразу прототип | Быстрый старт | Теряется связь требований, кода и проверки |
| Полный Specify CLI / Spec Kit | Готовые команды и шаблоны | Дополнительный инструмент, соглашения и сопровождение до ясности scope |
| Markdown, реестр спецификаций, PR и небольшая проверка | Прослеживаемый SDD без новых runtime-зависимостей | Дисциплина и содержательный review остаются ответственностью команды |

## Решение

Я выбрал третий вариант. Последовательность и разделение поведения, плана, задач и проверки опираются на [официальное описание Spec Kit](https://github.github.com/spec-kit/quickstart.html). Spec Kit здесь не установлен. Если инструментарий понадобится для следующих функций, оформлю его принятие отдельным ADR/PR.

Первоначальная база — Git и документы. Нет приложения, БД, облачных ресурсов и установленных проектных зависимостей. Основа приложения создаётся отдельным PR после уточнения спецификаций и визуального направления. Это позволяет выбрать технологии под поведение и избежать затрат на ненужную инфраструктуру.

## Последствия и проверка

Проект читается без специального CLI. Review требует реального внимания: успешный docs-check не доказывает качество сценария. Скрипт проверяет структуру и ссылки, а не заменяет человека. Статусы и ограничения должны быть видны в документах и PR. Переход к другому инструменту остаётся обратимым.
