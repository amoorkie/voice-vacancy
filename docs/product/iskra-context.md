# Место функции в «Искре»

10.11.2026. Контекст уточнён мной по интерфейсу компании. Переходы и интеграция ниже — предложение для следующего среза, а не проверенное поведение «Искры» или уже реализованная связь с ней.

## На что я опираюсь

- В исходном PDF задача названа новой функциональностью для сервиса автоматического найма. Название «Искра», точка входа и способ встраивания в нём не указаны.
- Я уточнил, что рассматриваю функцию как часть «Искры», и прислал снимок её рабочего интерфейса. На нём видны список вакансий слева и кнопка «Добавить вакансию» внизу. Состояние после нажатия не показано.
- На [официальной странице «Искры»](https://lpii.ru/iskra), проверенной 10.11.2026, описаны подключение вакансий и работа с откликами. Это подтверждает контекст найма, но не доказывает маршрут конкретной кнопки. Она может также служить подключению существующей вакансии.

## Как я предлагаю встроить сценарий

Предполагаемый путь: рабочий экран «Искры» → «Добавить вакансию» → создание через наше интервью → проверка и правка черновика → сохранение в «Искре» → карточка черновика.

Если «Добавить вакансию» уже открывает импорт или подключение, я сохраняю этот путь и добавляю отдельный вариант создания с помощником. Не заменяю существующее действие без проверки.

Для интервью я предлагаю отдельный просторный экран внутри продукта: название «Создание вакансии», узнаваемая навигация «Искры» и понятный возврат. Список кандидатов и аналитику на время интервью скрываю, чтобы они не отвлекали от ответа. Четыре темы, выбранную стеклянную кнопку и заполняющееся кольцо сохраняю. Voice Vacancy остаётся рабочим именем репозитория; самостоятельный логотип и рекламное вступление в продуктовом сценарии не нужны.

Основная работа J1 остаётся прежней: собрать требования к будущей роли. Вопросы адресованы человеку, знающему будущую работу сотрудника. Наличие HR-интерфейса не превращает этот сценарий в интервью кандидата и не доказывает, что все ответы знает рекрутер.

## Что необходимо определить до интеграции

| Вопрос | Моё предложение |
| --- | --- |
| Что сейчас делает «Добавить вакансию»? | Проверить фактический переход; сохранить подключение существующей вакансии, если оно есть |
| Как возвращаться из незавершённого интервью? | Явное действие «К вакансиям». При наличии несохранённых ответов — выбор остаться или выйти с предупреждением об их потере. Автосохранение не обещаю без реализации |
| Что означает «Завершить»? | Завершение интервью открывает обзор ответов. Выход в список и сохранение вакансии — отдельные действия |
| Что сохраняется после генерации? | Редактируемый черновик, без автоматической публикации или запуска найма. Дополнительные обязательные поля определяет контракт «Искры», а не выдуманные поля нашей формы |
| Когда показывать успех? | После подтверждения сохранения сервисом. При ошибке оставить текст и правки, дать повтор; повторная попытка не должна создавать дубликат |
| Нужна ли нам своя регистрация и БД? | Для демонстрации — нет. В интеграции использовать аккаунт, права и хранение принимающего продукта после согласования API |

Я не придумываю URL, API-поля, права доступа или статусы «Искры» по скриншоту. Для рабочего подключения нужны её контракт создания/сохранения, правила обязательных полей, ошибки и управление сеансом. До этого можно показать переход на тестовых данных, явно обозначив демонстрацию.

## Что есть сейчас

В PR #7 работает самостоятельный прототип интервью. Он ещё не открывается из «Искры», не сохраняет туда вакансию и не возвращается в её карточку. Его сводка и экспорт остаются рабочим выходом. Новую рамку фиксирую до изменения интерфейса; существующую приёмку UI не выдаю за приёмку интеграции.
