# Живая «Искра»: интерфейс, вход и референсы

10.11.2026. Исследование для следующего среза. Новую функцию здесь не считаю реализованной или принятой.

Я хочу встроить создание вакансии в рабочее место «Искры». Для этого поручил Codex изучить открытую страницу в моём Яндекс Браузере через отладку, снять экраны лендинга и найти основу для голосовой анимации. Мои три вложенных скриншота HireHi служат референсами панелей, а не источником фирменного стиля «Искры».

## Что проверено и каким способом

Браузерное расширение представило окно Яндекса как Chromium/Chrome. Использована существующая вкладка с заданным адресом. Проверены доступный интерфейс, DOM, ссылки, вычисленные стили и публичные демо. Данные аккаунта, вакансии и настройки сервиса не менялись. Микрофон и платные API не включались.

В конце кабинет возвращён на `/app/add`, лендинг — к началу.

## Что это меняет в прежних выводах

**Факт:** нынешнее «Добавить вакансию» ведёт к подключению вакансий. Оно не открывает форму голосового создания. Ссылка из пустого состояния ведёт на hh.ru. Поэтому новая панель — расширение продукта, а не восстановление уже существующего поведения. Источник: [живая страница](https://iskra.context8.ru/app/add), шаги 1–4.

**Моё предложение:** в демонстрации нижняя кнопка открывает новое интервью, как я задумал; в его заголовке остаётся отдельный путь «Подключить существующую». Для настоящей интеграции способ добавления должен согласовать владелец «Искры». API сохранения и статус внутреннего черновика из браузерного наблюдения не установлены.

**Факт:** в доступном кабинете нет вакансий; заполненную карточку и работу её кнопок проверить нельзя. Публичный лендинг показывает кандидатов, показатели, таблицы и тепловую карту. Это визуальное доказательство состава экрана, не проверка серверного поведения или качества подбора. Источник: [лендинг «Искры»](https://lpii.ru/iskra), шаг 5.

**Вывод:** я беру нейтральную оболочку из живого кабинета и плотность заполненных экранов из лендинга. Большие оранжевые рекламные блоки лендинга не переношу в рабочую форму. Метрики эффективности из маркетингового текста не считаю доказанным результатом нашего решения.

## На чём собран интерфейс

Предположение о shadcn хорошо подкреплено DOM: `data-slot` для sidebar, button, input и select-trigger, Radix-идентификаторы, cmdk, характерные наборы utility-классов. В ресурсах страницы есть Next.js chunks. Это совместимо с shadcn/Radix и Tailwind; точные версии, исходный репозиторий и все зависимости без доступа к коду не подтверждены. Лендинг отдельно собран на Tilda.

Вычисленные стили на desktop, 1920 × 928 CSS px:

| Элемент | Наблюдение |
| --- | --- |
| Основной фон / текст | `oklch(100% 0 0)` / `oklch(14.5% 0 0)` |
| Основная кнопка | `--primary: oklch(20.5% 0 0)` |
| Вторичный фон / текст | `oklch(97% 0 0)` / `oklch(55.6% 0 0)` |
| Граница / sidebar | `oklch(92.2% 0 0)` / `oklch(98.5% 0 0)` |
| Радиусы | Базовый токен `.625rem`; у просмотренных контролов 8 px |
| Шрифт | Системный sans; заголовок 20/28 px, вес 500; контролы 14 px |
| Геометрия | Sidebar 256 px; отступ основного содержимого 24 px; контролы 32–36 px |

Эти значения — отправная точка для оболочки. Размеры новой панели и шара ниже являются моим дизайном, а не измерениями существующей формы.

## Как использую мои скриншоты панелей

Из HireHi беру отделённую от краёв округлую поверхность, затемнение/размытие фона, кнопку закрытия, внутреннюю прокрутку и возможное разделение на две области. Цвета, тексты, тарифы и содержимое чатов не переношу. Статичные вложения не доказывают направление и длительность анимации: движение описываю как своё предложение.

## Готовые основы для шара

| Основа | Подтверждено | Ограничение и мой выбор |
| --- | --- | --- |
| [ios-siri-animation](https://github.com/neeldedkawala/ios-siri-animation), [демо](https://ios-siri-animation.vercel.app/) | Three.js/GLSL, стеклянный эффект и цветная волна; [MIT](https://github.com/neeldedkawala/ios-siri-animation/blob/main/LICENSE). Эффект просмотрен в браузере | Визуально ближе к Siri. Предлагаю отдельную пробу адаптации эффекта под наш круг. Это демо телефона, не готовый React-компонент для формы; телефон, обои и значки не нужны |
| [ElevenLabs Orb](https://ui.elevenlabs.io/docs/components/orb) | React, Three.js, состояния, ручная громкость; [исходник](https://github.com/elevenlabs/ui/blob/main/apps/www/registry/elevenlabs-ui/ui/orb.tsx), [MIT](https://github.com/elevenlabs/ui/blob/main/LICENSE.md) | Проще интегрировать, но внешний вид демо заметно отличается от выбранного стеклянного микрофона. Использую как технический ориентир и запасной вариант, не подменяю им утверждённый образ без сравнения |
| [siriwave](https://github.com/kopiro/siriwave) | Canvas, классические волны, управление амплитудой, MIT | Не готовый стеклянный шар; bubble в README обозначен как незавершённый. Для главного элемента не выбираю |

В исходнике ElevenLabs Orb нет требования к ключу ElevenLabs: громкость передаётся компоненту. Но есть внешняя текстура `perlin-noise.png` с Google Storage. Поэтому «без платного API» не означает «полностью автономно»: при выборе этой основы заменю зависимость локальным или процедурным шумом, проверю условия использования ассетов и сохраню уведомление MIT. Совместимость с нашим React 19, вес сборки, скорость на мобильном и очистка WebGL пока не проверены. Сторонний код в проект не установлен.

Я не называю эти эффекты официальной реализацией Apple. Рекомендации [Apple Siri HIG](https://developer.apple.com/design/human-interface-guidelines/siri) относятся к взаимодействию и платформе, не предоставляют готовый web-шейдер.

## Технические выводы

- Для панелей подходит [shadcn Sheet на Radix](https://ui.shadcn.com/docs/components/radix/sheet). Один управляемый модальный контейнер с двумя внутренними панелями проще двух независимых диалогов. [Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog) задаёт основу для фокуса, заголовка и Escape; поведение стека нужно проверить отдельно.
- Реакция на голос строится на локальном Web Audio: [AnalyserNode](https://developer.mozilla.org/en-US/docs/Web/API/AnalyserNode/getFloatTimeDomainData) даёт отсчёты сигнала, по ним считаю сглаженную громкость. Это визуализация звука, не распознавание смысла или прогресса.
- Для расшифровки нужен отдельный ASR-контракт. [SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition) имеет ограниченную совместимость, поэтому не выбираю его единственной опорой для Яндекса, Chrome и Edge. Возможность распознавания у моего шлюза ещё не подтверждена.
- Наличие Next.js у «Искры» не требует переносить наш React/Vite-прототип на другой фреймворк. Для демонстрации достаточно общей структуры компонентов, токенов и отдельного адаптера будущей интеграции.

## Приоритеты следующего среза

| Приоритет | Слабое место | Что предлагаю проверить |
| --- | --- | --- |
| Высокий | Создание смешано с подключением вакансии, шаги 1–4 | Отдельные понятные действия, сохранён путь подключения |
| Высокий | Анимация голоса может выглядеть как принятый ответ | Внутри — активность звука, снаружи — четыре подтверждения; подпись «Темы: N из 4» |
| Высокий | Два слоя могут скрыть правки или сломать фокус | Один модальный контейнер, возврат без потерь, явное устаревание результата |
| Средний | Пустой кабинет не показывает место новой функции | Связанный синтетический набор вакансий и откликов в локальном демо |
| Средний | Шейдер может тормозить или не запуститься | Отдельная проба, reduced motion, статический fallback, замеры до включения |

Это разбор конкретного сценария, а не полный аудит доступности или всего продукта. Предложение для реализации, состояния и критерии — в [спеке двух панелей](../technical/iskra-double-sheet.md).
