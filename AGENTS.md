# Правила Voice Vacancy

## Назначение

Создать небольшой рабочий прототип голосового интервью для подготовки вакансии. Демонстрировать прослеживаемый spec-driven development.

## Порядок работы

1. Начать с относящейся к задаче спеки. Это источник требований. Для её обоснования читать исходную задачу, решения владельца и исследования по ссылкам в `docs/README.md`.
2. В спеке описать проблему, наблюдаемое поведение и границы. По спеке составить план с JTBD, пользовательским флоу, техническими решениями и проверками. По плану составить задачи с зависимостями и результатом. При изменении поведения обновить документы в этом порядке.
3. Статус `draft` не разрешает реализацию. Владелец принимает продуктовые предположения и спецификацию; статус и основание записываются в ней.
4. Делать небольшие PR с одной понятной целью. Изменение поведения требует обновления спецификации до реализации.
5. В PR связывать требования, изменения и результаты проверок. Не выдавать наличие документа за готовность продукта.
6. Не сливать PR, не менять видимость репозитория и не выкладывать приложение без отдельного разрешения владельца.

## Доказательства и границы

- Отделять факты первичных источников, выводы команды, гипотезы и вопросы владельцу.
- Не выдумывать интервью, результаты тестов, проценты использования ИИ или скорость выполнения задания.
- Не добавлять оригинальный PDF, секреты, реальные голосовые записи и персональные данные в Git.
- Не подключать платные сервисы и не отправлять пользовательское аудио внешнему провайдеру без согласованной спецификации обработки данных.
- Документация на русском. Поясняющие комментарии создаваемого и изменяемого кода на русском; имена API и машинные директивы сохраняются.
- Авторские описания решений, процесса и PR писать от первого лица владельца («я») простым языком. Роль Codex указывать честно; не приписывать владельцу ручные проверки и действия, которых он не выполнял. Требования, поля данных и цитаты сохраняют нужный формат.
- Не добавлять в описания PR и продуктовые пояснения редакторские абзацы о том, от какого лица написан текст, и повторяющиеся оговорки о независимости агента. Фактическое участие ИИ описывать в журнале процесса без таких вводных.
- Не вводить БД, авторизацию и инфраструктуру без требования, которое объясняет их необходимость.
- Визуальное направление определяется отдельно до реализации интерфейса.
